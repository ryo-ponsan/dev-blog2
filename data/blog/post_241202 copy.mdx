# クエリの最適化:クエリセットの設計

- モデル間のリレーションを利用した効率的なフィルタリング（例: select_related, prefetch_related）を活用。
- フロントエンドやAPIレスポンスの要件を考慮して必要なフィールドだけを取得するクエリセットを設計。
- 大量データがある場合、必要なフィールドだけを取得するようにクエリを設計。

- Djangoでは、外部キー（ForeignKey）や多対多（ManyToManyField）などのリレーションを定義してモデル間を結びつけている
- DjangoのQuerySetでは、必要なフィールドだけを指定してデータを取得可能
- データ転送量の削減
    - データベースからアプリケーションに送信されるデータ量を減らし、処理を高速化。
- メモリ使用量の削減
    - 必要なフィールドだけ保持することで、サーバーのメモリ使用量を抑制。
- パフォーマンス向上
    - 大量データの処理でも必要最低限の情報に絞ることで効率的

# 1.必要なデータだけを取得する`@TODO`
不要なデータをクエリで取得していると、メモリ消費やネットワーク転送が無駄に増加する。

### 手法
- 日記投稿・編集で、クエリセットを変更
- 全フィールドを取得しない。必要なカラムのみ取得

### 効果
メモリ使用量や転送データ量の削減、クエリ実行速度の向上。

### 実際の結果(PoDDiary)

```python
# 全てのポッドキャストのタイトルだけ取得
podcasts = Podcast.objects.only('title')

# 結果を辞書形式で取得（例: APIレスポンス用）
podcast_data = Podcast.objects.values('title', 'spotify_url')

```


# 2.リレーションデータの効率的な取得（N+1問題の回避）
外部キーやリレーションを持つデータを取得する際、データベースへのクエリが大量に発生

### 手法
- select_related:
    - 外部キーで結ばれたリレーションを1つのクエリで取得。
    - 例: ユーザーのプロフィール情報を同時に取得。
- prefetch_related
    - 多対多（ManyToManyField）や逆参照関係のデータを効率的に取得

### 効果
クエリ回数の削減（1回のクエリで関連データも取得）

# 4.クエリの計測と最適化`@TODO`
get_my_page_diariesでできる。

特定のクエリが遅い原因を特定し、最適化する。
### 手法
- Django Debug Toolbar:
    - 実行されたSQLクエリを確認し、どのクエリが遅いかを特定。
- EXPLAINコマンド:
    - SQLの実行計画を確認して、テーブルスキャンが発生していないか調査。
- SET log_min_duration_statement:
    - 遅いクエリをPostgreSQLログに記録。

### 効果
- 遅いクエリを特定し、適切なインデックスや設計変更で解決。

- クライアント側でのデータ処理効率の向上。

# 6.バルク処理
複数のレコードを1件ずつ更新する処理が非効率。

### 手法
- Djangoのbulk_createやbulk_updateを使用して、1回のクエリで複数レコードを処理。
- 例: 100件のデータを1回のクエリで挿入。

### 効果
- クエリの回数を削減し、処理時間を短縮。
